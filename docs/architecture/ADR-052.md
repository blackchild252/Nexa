# ADR-052 — Reversible Preview Workflow Data

## Decision

NEXA preview/demo data may populate real Consumer and Admin workflow surfaces for launch testing, but it must remain explicitly gated, identifiable, and removable without changing production authorities.

## Rules

- Seed only when `NEXA_PREVIEW_MODE=1`.
- Use deterministic `demo_*` identifiers for the new preview layer where practical.
- Keep demo money and provider-dependent experiences non-production.
- Do not fabricate live Ball House/Game House provider truth.
- Keep showcase items such as Blaca Essentials explicitly tracked for removal.
- Cleanup must cover both the new `demo_*` layer and older deterministic preview identities/vendors.
- Demo records may exercise real UI/API workflows but never bypass authorization, payment verification, moderation or Admin authority rules.

## Consequence

Launch testers can inspect populated screens and exercise buyer/seller/Admin workflows before live customer data exists. Final production certification requires preview mode disabled and controlled cleanup verified.
