# ADR-038 — Complete Adaptive Learning Follow-Up Lifecycle

## Decision
Dami and Admin Operations adaptive-learning follow-ups support three user-owned lifecycle outcomes: pending/overdue, completed, and cancelled. Completion and cancellation are server-authorized by both user and AI profile and emit bounded canonical audit events.

Learning state also exposes a derived list of active topics for the current owner/profile. Topic aggregation is informational only and cannot grant permissions or alter canonical business data.

## Rationale
A follow-up that can only be completed but not cancelled leaves stale user intent in the adaptive context. Topic-level controls also need a reliable state representation so the UI can explain what can be forgotten without scanning raw records.

## Boundaries
- Server authorization remains authoritative.
- Consumer Dami and Admin Operations remain separate AI profiles.
- Adaptive memory is non-authoritative and user-removable.
- Audit metadata is sanitized through the existing event-correlation boundary.
- No autonomous model-weight updates or authorization decisions are introduced.
